## Structure of the fight

- No single model owns this board: Opus-5.0 holds the deep-reasoning rows
  (HLE, Terminal-Bench 3.0/4.0, ProgramBench, NL2Repo, Chartography,
  BabyVision); DS-V4.1-Flash holds most agentic rows (TB 2.1, DeepSWE,
  CyberGym, Codeforces, AutomationBench, Agent's Last Exam, HLE w/ tools);
  GPT-5.6 Sol holds GPQA Diamond, SEC-Bench Pro, ExploitGym, ZeroBench.
  "Annihilate" = clearing seven different specialist peaks, row by row.
- Guarantee-native front (separate board): verified-certificate coverage,
  certified self-knowledge AUROC, abstain-with-proof rate — frontier scores
  ~0 by construction; XIIV leads there by design (CSM ledger AUROC 0.721
  measured 2026-10-21). This front is already ours to lose.
- Capability front (this board): climb = trained 1B → 800B-class sparse
  growth → Forge/Adaptive verified compounding → test-time compute scaling
  (selective looping prototype queued). First real readings the day the
  trained 1B is assembled: GPQA Diamond + HLE first (pure-model rows);
  agentic rows need the Forge harness and follow.
- Mythos (Claude) and GPT Astra 6 are Fahad's named apex targets; the table's
  Opus-5.0 / GPT-5.6 Sol columns are the closest published proxies on file.

## Attack plan per row (set 2026-10-22, Fahad's directive: beat at any cost)

"At any cost" = maximal effort + invention around every blocker. It never
means fabricated numbers — one exposed fake score detonates the release;
our brand is that every published number survives any audit.

- **Pure reasoning rows** (GPQA Diamond, HLE, MathArena Apex): capability
  ceiling from scale (800B-class growth) + reasoning data emphasis
  (OpenThoughts3 3x-epoch replay) + test-time compute (inference loop
  scaling; certificate-guided generate→verify→refine where answers are
  checkable converts directly into pass@1).
- **Coding / agentic rows** (Terminal-Bench 2.1/3.0/4.0, DeepSWE,
  ProgramBench, NL2Repo, AutomationBench, Agent's Last Exam): Forge
  harness + Adaptive subsystem 1 (verifiable-reward RL) + subsystems 2/4
  (adversarial self-play inside executable task environments). These rows
  are natively verifiable — tests pass or fail — so the independent
  verifier is a direct training weapon here, not just a judge.
- **Security rows** (CyberGym, SEC-Bench Pro, ExploitGym): same
  verifiable-reward loop, security task environments; Fahad's own domain.
- **Tool / multimodal-tool rows** (Chartography, BabyVision, ZeroBench,
  HLE w/ tools): tool-use harness + vision path (in code, untrained today —
  longest pole, flagged honestly).
- **Gate discipline:** every row gets a named mechanism + a measured run;
  first readings at trained-1B assembly (GPQA + HLE first). A row with no
  mechanism is a wish; this board has none of those.
