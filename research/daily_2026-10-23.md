# Daily research sweep — 2026-10-23

Scope: latest (2024–2026, emphasis last ~6 months) in 5 areas, assessed vs XIIV's masked-diffusion + guarantee-native thesis. Rule: absorb, never copy; prior-art notes for invention hygiene. All items sourced from pages opened or search results seen today.

## 1. Masked diffusion LMs

- **Fast-dLLM** (ICLR 2026, NVIDIA/HKU; nvlabs.github.io/Fast-dLLM) — block-wise *approximate* KV cache for bidirectional diffusion models + confidence-aware parallel decoding (decode only tokens above a confidence threshold); up to 27.6× throughput with minimal accuracy loss.
  Fit: **partial** — KV cache tricks are engineering, not guarantees; but confidence-aware parallel decoding is sampler-level and maps to XIIV's reverse process. Port-worthy, not invention.
- **Discrete Diffusion Forcing (D2F)** (ICLR 2026; iclr.cc/virtual/2026/poster/10007008) — block-wise causal attention + KV cache reuse via asymmetric distillation; first dLLMs measured >2.5× faster than AR LLMs of equal size, >50× over vanilla dLLMs at equal quality.
  Fit: **partial** — speed axis only; no proof axis. Useful reference for the day XIIV-1B serves.
- **Fast-dLLM v2** (ICLR 2026) — block-diffusion recipe that converts a pretrained AR checkpoint into a dLLM with only ~1B tokens of fine-tuning (500× less than Dream's 580B), preserving performance; hierarchical block + sub-block caches.
  Fit: **partial** — conversion recipe could matter for future AR→diffusion migration; not our lane (XIIV is native diffusion).
- **LLaDA2.0** (2025, Bie et al.) — scales masked diffusion to 100B via a 3-phase block-level scheme.
  Fit: **no-fit** — pure scale play, no guarantee content; confirms blockwise scaling works, which is a side-evidence note for the 5B sparse ladder only.

## 2. Guarantee-native / constrained generation / proof-carrying outputs

- **LAVE: Lookahead-then-Verify** (arXiv:2602.00612, ISSTA 2026; Tsinghua/Peking/Beihang) — constrained decoding purpose-built for dLLMs under context-free grammars: propose token, run lookahead verification that the partial output remains extendable to a valid sentence, reject otherwise; plus cache-enhanced recovery from the last verified prefix. Near-100% syntactic@k on JSON/C++/SMILES benches (e.g., 66.0%→98.7% syntactic@1 on SMILES with LLaDA-8B) with negligible runtime overhead.
  Fit: **strong fit** — the first verify-before-commit scheme for *diffusion* sampling, not AR; XIIV's verifier is stronger (proof certificates, not CFGs). We must NOT copy LAVE; but the *pattern* (lookahead + verified-prefix cache + recovery) is the exact sampler shape our guarantee-native layer wants.
- **Type-Constrained Code Generation** (ETH SRI, Oct 2026; eth-sri.github.io) — prefix automata + sound type-inference search enforce *well-typedness* during decoding; compilation errors more than halved on HumanEval-family tasks across model sizes.
  Fit: **partial** — semantic-level constraints (types) are closer to our semantic certificates than CFG syntax is; mechanism is AR-prefix-automata, not diffusion-native.
- **VERIFY dataset** (ICLR 2026; proceedings.iclr.cc) — NL↔temporal-logic benchmark; best model only 31.5% semantic equivalence NL→LTL, 41% of failures from wrong operator scope — attributed to unconstrained decoding being structurally wrong for formal output.
  Fit: **fit (evidence)** — independent confirmation that guarantees must live in the decoding loop, not in the prompt. Supports our thesis; no mechanism to port.
- **ProVe: Proposer-Verifier Decoding** (arXiv:2610.27815, 20 Oct 2026) — fine-tunes a large model into a block-proposer, verifies with one forward pass; 2.5× AR throughput.
  Fit: **no-fit** — speedup play, verifier is accuracy-check not proof-check. Name collision risk noted: do NOT name anything "ProVe".

## 3. Parameter-efficient training

- **CeRA** (arXiv:2602.22911, Apr 2026; Hung-Hsuan Chen) — attacks LoRA's "linear ceiling": weight-level parallel adapter with SiLU gating + dropout for *non-linear* capacity expansion; rank-64 CeRA beats rank-512 LoRA on MATH (16.36% vs 15.72% pass@1) and DoRA rank-64 (14.44%); spectral analysis shows it uses the lower-variance tail LoRA leaves dead.
  Fit: **partial** — genuinely interesting and CPU-implementable for our LoRA adapters, but a direct port of someone else's mechanism; non-mergeability (non-linear ⇒ can't merge into base weights) needs checking against our adapter-serving path.
- **RaLoRA / RaLoRA-Pro** (ICLR 2026; proceedings.iclr.cc) — entropy-based estimator of gradient intrinsic dimensionality per layer; aligns LoRA rank to layer-wise GID, narrows the LoRA↔full-finetune gap (+5.23% GSM8K, +5.69% HumanEval over vanilla LoRA).
  Fit: **partial** — rank-allocation hygiene, orthogonal to most variants; could inform our SGBD/LoRA configs. Port, not invention.
- **OrthoGeoLoRA** (arXiv:2601.09185, Jan 2026) — enforces SVD-like ΔW = BΣAᵀ with Stiefel-manifold orthogonality; geometric reparameterization, Adam-compatible.
  Fit: **partial** — CPU-friendly code, stability benefits plausible; standard LoRA port.
- **PARA** (arXiv:2604.27796, Apr 2026) — data-free post-hoc SVD rank pruning with a global singular-value threshold; 75–90% parameter reduction with preserved accuracy.
  Fit: **partial** — useful *after* adapters exist (storage/portability), zero training change. Possible follow-up, not today's pick.

## 4. CPU / low-memory training

- **GaLore 2** (arXiv:2504.20437, Apr 2025) — fast randomized SVD + FSDP + low-bit quantization support; 7B on 500B tokens at ~63% memory savings vs BF16 Adam.
  Fit: **partial** — GPU-cluster oriented; randomized-SVD subspace updates are the idea most portable to our CPU budget, but we already do cached-activation block training.
- **QuZO** (arXiv:2502.12346, Feb 2025) — *zeroth-order* quantized training: forward-only, no backprop; hardware cost ≈ post-training quantization; beats/surpasses truly-quantized first-order fine-tuning at 4-bit.
  Fit: **partial** — the forward-only property is genuinely interesting for a 7GB box (no activation storage), but zeroth-order needs many forward evals; worth a probe, not a pick.
- **BitNet b1.58** (Microsoft 2025; 2B4T open weights) — native ternary training {-1,0,+1}, 0.4GB non-embedding footprint, 29ms/token CPU decode; needs bitnet.cpp to realize gains.
  Fit: **no-fit** — training-native 1.58-bit needs full retrain; XIIV's precision lives in certificates, not weight bits. Side-note only.
- **Dynamic Memory Sparsification / DMS** (Univ. Edinburgh + NVIDIA, Dec 2025) — compresses KV cache 8× by evicting tokens judged unimportant, with a delayed-eviction window that lets the model transfer information to surviving tokens; *better* math/science/coding scores at 1/8 memory.
  Fit: **partial** — inference-side; the "transfer-before-evict" trick is a neat pattern for any future long-context work.

## 5. Attention / sampling / architecture

- **Log-Linear Attention** (arXiv:2506.04761, v3 Mar 2026) — hierarchical state structure between linear and quadratic: O(T log T) training, O(log T) decoding, fixes linear attention's associative-recall weakness (the known Arora et al. limitation).
  Fit: **partial** — XIIV's context is 128→1024 staged; attention is not our bottleneck. Watch for the 5B's 1024-context phase.
- **DeltaNet / Gated DeltaNet** (2024–2025 lineage, in the log-linear paper's unified table) — delta-rule structured transitions (fast-weight dynamics) with data-dependent gates; the current best linear-recurrent family on recall.
  Fit: **partial** — same verdict as above; architecture thesis is diffusion+guarantees, not attention variants.
- **HyperAttention** (2023; still the near-linear reference) — LSH-based large-entry detection + spectral guarantee on the approximation, up to 50% faster than FlashAttention at 32k.
  Fit: **no-fit** — GPU-kernel play, 2023 vintage, nothing for a CPU diffusion box.
- **Confidence-based early-exit denoising** (seen inside dLLM-ASR, arXiv:2601.17902) — tokens that converge exit the denoising loop early; token-level adaptive compute.
  Fit: **partial** — sampler-level, cheap, and directly portable to XIIV's reverse loop. Consider bundling into the pick.

## THE PICK — candidate XIIV invention

**Certificate-Gated Adaptive Unmasking (CGAU)** — the first *proof-certificate-gated* sampler for a masked diffusion LM.

Nothing in the sweep does this. LAVE gates diffusion proposals on CFG syntax; type-constrained decoding gates AR prefixes on type automata; QuZO-style zeroth-order and CeRA-style adapters are orthogonal. No paper gates each unmask step on whether the partial assignment remains *extendable to a verified proof certificate* (XIIV's Presburger/abstract-interpretation witnesses). That gap is ours to claim.

Sketch:
1. At each reverse-diffusion step, take the model's top-k confidence proposals for masked positions (standard MDLM unmasking).
2. Before committing, run the existing `xiiv/contracts.py` verifier on the partially-unmasked sequence as a *prefix-certificate check*: can this partial assignment still extend to a fully certified output? Proposals that keep the certificate extendable are committed; failures are re-masked (never committed unverified).
3. Keep a cache of the last fully-certified prefix; on repeated failures (a stall), roll back to it — the recovery pattern LAVE validated, but for proof state instead of syntax.
4. Fold in the confidence-early-exit trick (from dLLM-ASR): positions whose certificate margin is saturated skip further denoising passes, cutting CPU cost.
5. Measurable falsifiers (CPU-testable on the compositional proof machine, depths 1→100): certificate-failure rate per unmask step vs vanilla confidence unmasking; final-output validity; steps-to-valid-certificate. Kill if no separation on failure rate.

Why it clears the bar: no GPU needed (pure sampler logic + existing verifier), small code surface (a sampling loop + verifier hook), fits the thesis exactly ("every answer carries its proof" *enforced at generation time*), and it is genuinely novel — verification-gated sampling for diffusion exists only at the syntactic level (LAVE); semantic proof-certificate gating does not. Absorb LAVE's lookahead/recovery pattern as prior-art inspiration; invent the certificate-gating mechanism ourselves.

**Closest miss:** CeRA (non-linear LoRA). CPU-implementable, one-day build, plausibly helps our 2.21M-param adapter — but it's a port of Chen's mechanism with no XIIV-native angle, and the non-linearity may break adapter mergeability into the base. Revisit only if CGAU's falsifiers fail.
