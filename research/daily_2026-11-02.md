## Part A — research findings (2025-2026, fresh ground)

Ranked sweep (subagent; full report in run handoff):

1. **CoDR — Confidence-Drift Remasking** (Wu et al., arXiv:2610.08833,
   28 Sep 2026): training-free refinement for masked diffusion LMs.
   Errors come from *confidence drift* -- a token committed under sparse
   context loses model endorsement once context densifies. k-partition
   probing estimates drift in k forward passes; drifted tokens are
   remasked + regenerated. Fit: HIGH -- diffusion-native, training-free,
   CPU-verifiable, absent from our codebase. **THE PICK (mechanism).**
2. **"Remask, Don't Replace" / Token-to-Mask** (arXiv:2604.18738):
   detection/correction decoupling, LOGITDIFF detector, stuck-set
   theory (T2T provably cannot self-correct some errors; 41.3% of
   last-mile corruption repaired). Fit: HIGH -- absorbed as inspiration
   for the decoupled probe/repair split.
3. **TPP vs LCR** (Jeon et al., arXiv:2609.34509, Oct 2026): sharp
   result -- low-confidence remasking (commit only the single
   highest-probability proposal across positions) exponentially
   suppresses lower-probability tokens as positions compete (diversity
   collapse, observed in LLaDA); top-probability *position* selection
   (pick position by max top-token prob, then sample its distribution)
   preserves the joint. Fit: HIGH -- one-line rule correction; our
   samplers audited: all position-first (TPP) by construction, locked
   by a new falsifier (F4).
4. **EPIC** (arXiv:2606.00722): fixes the 4x slowdown of Mündler-style
   CFG-constrained diffusion decoding (lexing memoization + relaxed
   compatible subset selection, -67.2% inference time). Fit: MEDIUM --
   would be an efficiency upgrade to CGEC, not a new capability. Filed.
5. **SchED** (ACL 2026 Findings): progress-aware confidence schedules,
   ~4x early-exit speedups. Fit: LOW -- CGEC already does confidence-gap
   early commit; only delta is progress-dependence. Filed.
6. **Spiffy** (arXiv:2509.18085, Qualcomm): lossless speculative
   decoding for dLLMs, 2.8-3.1x. Fit: NONE for the guarantee thesis
   (speeds up the distribution, says nothing about guarantees). Pass.
7. **LAVE** (ISSTA 2026): lookahead-then-verify CFG decoding, fixes
   Mündler's length-overapproximation. Fit: MEDIUM -- CGEC already does
   per-commit grammar reachability gating; LAVE is a refinement. Filed.
8. **SCALE** (arXiv:2506.16659): minimalist optimizer (column-wise grad
   norm + output-layer momentum), beats GaLore at ~59% memory. Fit:
   NONE today -- could cut Kaggle-T4 trainer memory, but swapping
   optimizers into the Nov-5 kernels the week of launch would be
   reckless. Flagged as a leg-4+ candidate only.

Deliberately excluded (already in prior-art notes or need training):
D2F, Fast-dLLM, ReMDM, RCD, RemeDi/DSC/PRISM, dSpark, Saguaro.

**THE ONE PICK -- Certificate-Drift Remasking (CDR).** Ports CoDR's
drift-detection *mechanism* (k-partition probing: re-mask each
partition, measure endorsement under the denser context, remask what
decayed) but replaces the drift *signal*: instead of the model's
confidence, CDR tracks the **independent certificate margin** -- the
verifier's endorsement of the committed token under commit-time
context vs current context. The synthesis: CoDR asks "does the *model*
still endorse this token?" and fails exactly when the model is
confidently wrong; CDR asks "does the *proof* still endorse this
token?" No 2024-2026 work remasks on verifier-margin decay (closest is
DCMR, which remasks on current-state breach, not drift). Pre-registered
falsifier F2 can honestly kill the synthesis half: if certificate mode
adds nothing over confidence mode on the deceptive stub, only the CoDR
port survives.

## Part B — implemented: `xiiv/cdr.py` + `tests/test_cdr.py` + `--cdr` CLI

Design (see module docstring for the full spec):
- Same `model(x: LongTensor(1,L)) -> logits(1,L,V)` interface as
  DCMR/CGEC. Vanilla confidence commits (no commit gate -- the drift
  story requires commits to happen first), TPP order (position by its
  own max top-token prob; anti-LCR).
- Per commit, records `endorse_commit`: P(token) for
  signal="confidence" (CoDR-faithful), verifier margin (1.0 clean /
  0.0 breach on the no-repeat-n-gram certificate) for
  signal="certificate".
- Every check cycle (default every step): confidence -> k-partition
  model probing (k forward passes); certificate -> full-canvas verifier
  re-read, ZERO forward passes (the synthesis dividend -- the verifier
  needs no model to re-endorse).
- Two remask rules: DRIFT (endorse_commit - endorse_now > tau) and
  STILLBORN (never endorsed even at commit: below conf_floor /
  cert_floor). Remasked tokens are tabooed (loop-breaker), then one
  decoupled regen pass on the cleaned canvas.
- Fail-closed: a completed canvas that breaches the certificate gets
  completed=False, never a certified emit. Emits a `cdr-v1`
  certificate dict per run (tokens + commit order + remask events with
  rule/drift; honestly flags `replay_needs_model` for the confidence
  signal).

Test results (CPU scripted stubs, `.venv/bin/python -m pytest
tests/test_cdr.py`): **11/11 pass**, including:
- F1 soundness on the repeater (certificate mode): completed,
  repeat-free, non-vacuous (remasks > 0).
- **F2 synthesis gate on the deceptive stub** (model stays confident
  on the repeat token forever), measured: certificate mode -> 8 drift
  remasks (drift values exactly 1.0, binary margin decay) + 8
  stillborn remasks, 2 regen passes, completed=True, final canvas
  repeat-free, **8 forward passes total, 0 probe passes**; confidence
  mode -> drift_remasks == 0, 10 probe passes burned seeing nothing,
  14 forward passes total, fail-closed (completed=False, repeats
  remain). The synthesis claim SURVIVES its falsifier: the proof rots
  where the model doesn't flinch -- and the verifier-signal repair
  cost fewer forward passes (8) than the blind confidence probing
  (14).
- F3 pass budget structural: certificate probe_passes == 0;
  forward_passes == commit_passes + probe_passes + regen_passes
  exactly, both signals.
- F4 TPP order locked: highest own-max position commits first, every
  position keeps its own top token (no global-proposal collapse).
- T1: confidence port catches the committed liar (drift 0.93 at the
  liar position, token corrected on regen); T3: honest stable model
  passes untouched under both signals (zero false remasks).

Honest limits (stated in code + tests, not hyped):
- Measured on CPU scripted stubs only -- real-checkpoint behavior
  untested (same standing caveat as DCMR/CGEC).
- The binary certificate margin fires at breach formation, not before;
  a graded "repeat-pressure" margin that predicts rot pre-breach is
  future work (noted, not claimed).
- `--cdr` wired into `xiiv/sample.py` generate path (plain generate
  only, like --dcmr/--cgec); default signal="certificate".
