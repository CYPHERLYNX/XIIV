### Screened papers (all from search-result abstracts, not read papers; their numbers are the papers' own claims, not XIIV measurements)

**Directly adopted (recipe for today's implementation):**

- **TIPS: A Tiny Inference-time Policy for Scaling in Diffusion Language
  Models** (arXiv:2610.22099): a ~600K-param controller that learns
  unmasking AND remasking around a frozen dLLM backbone, trained by
  supervised warmup followed by RL from terminal correctness rewards.
  LLaDA-8B-Instruct: 58.46% micro-averaged accuracy at 32 decoder
  evaluations on GSM8K/MATH-500, +12.1pp over the strongest baseline.
  Recipe adopted wholesale: tiny policy + supervised warmup now, RL from
  terminal (here: certificate) correctness next. The oracle differs: TIPS's
  reward is task correctness; ours is the independent certificate verifier
  + exact symbolic target equality.
- **What Makes a Good Unmasking Policy? A Controlled Study of Learned
  Unmasking in Diffusion Language Models** (arXiv:2610.31576): supervised
  policies distill a decoding procedure through a teacher; labeling
  predictions that merely match the final output is overly permissive at
  low NFE (28.7% of such positives leave the reference trajectory); the
  winning supervision is *trajectory-contraction targets* — accept only
  commitments staying on a reference trajectory. Their 856K-param policy
  (confidence + hidden states) achieves the best accuracy–NFE frontier on
  GSM8K and largely transfers to Dream-7B. Adopted as the supervision
  discipline: the deterministic VRC planner's plans ARE the reference
  trajectory; the policy is only ever shown plans that stay on it.
- **Verifier-Grounded Agentic RL for Provably Correct Code**
  (arXiv:2610.19298): a verifier-as-reward must be *dense* (weighted
  fraction of proof obligations discharged, not binary accept/reject) and
  needs an *integrity audit that outranks the verifier* (reject any
  candidate that alters the specification or assumes what it was meant to
  prove). DafnyBench 66.1% → 93.5%, SWE-Proof 56.3% → 100% (their claims).
  Adopted as the design for the RL stage: dense reward = fraction of
  certificate obligations discharged; integrity audit = exact symbolic
  target equality.
- **Verified but Vacuous: Three Failure Surfaces of LLM-Driven Verified
  Code Generation** (arXiv:2611.05590, IBM): 99.1% verifier acceptance,
  only 1.9% of certificates non-vacuous — RL against a binary verifier
  reward learns to eliminate proof obligations. Adopted as a design
  constraint, not a method: our evaluation's honest metric is
  `verified_success` (certificate verifies AND concrete == symbolic AND
  final value equals the target), never certificate validity alone. A
  policy that "verifies" a trivial plan that misses the target scores 0.

## Part B — implementation: Phase-2 supervised warmup

**Files:** `research/proof_machine/phase2/` — `gen_dataset.py`,
`policy.py`, `train_policy.py`, `eval_policy.py`, `test_phase2.py`,
`README.md`, `data/` (8,000 train / 1,500 test, seed 20261116),
`results/train_log.json`, `results/eval_step1_20261116_015457.json`.
Checkpoint `phase2/checkpoints/policy_step1.pt` is local-only (binary,
not pushed).

### Method

- Dataset: random affine specs (op chains from x0: ADD ±{1,3,7}, MUL
  ±{2,5}, NEG, MOD {7,13}) labeled by the deterministic VRC planner.
  Filters counted, never silent: duplicate 11,386 / plan-too-long 1,241 /
  probe-out-of-bound 192 (train attempts). Plan lengths 1–16.
- Model: encoder-decoder transformer, d=128, 2+2 layers, 668,683 params
  (TIPS scale). Char-level spec input, op-level output, greedy decode.
- Training: Adam 1e-3, cosine, batch 64, 25 epochs, CPU, 28.5 min.
  Final train loss 0.107, val token accuracy 0.975 (500 held-out).

### Measured (pre-registered protocol, n=1500 held-out, greedy decode)

| Metric | Result |
|---|---|
| exact_match (== planner plan) | **81.9%** |
| verified_success (solves the spec) | **83.3%** |
| alt_valid (verified but not exact) | 1.4% |
| invalid (empty plan) | 0.0% |

By planner-plan-length bucket (exact / verified): 1–3: 90.9% / 95.5%
(n=22); 4–6: 90.9% / 92.4% (n=540); 7–9: 87.8% / 88.7% (n=556); 10–12:
71.3% / 72.4% (n=254); 13–16: 38.3% / 41.4% (n=128).

All 250 failures are `target-mismatch`: the predicted plan executes and
its certificate verifies, but it computes a different function than the
target. Zero `neural-divergence`, zero `cert-invalid`, zero empty plans.
The oracle held — no vacuous certificate shipped; target equality caught
every failure.

### Reading (honest)

Supervised imitation of the planner works well to ~9 ops, then degrades
steeply (41% verified at 13–16 ops). The learned policy shows its own
compositionality wall — the same shape Phase 1 measured for the
transformer baseline, at a much higher level. The deterministic planner
stays 100% by construction at every length; the learned policy is judged
on generalization, not on beating it. The 1.4% alt_valid shows the policy
sometimes finds genuinely different valid plans — the seed the RL stage
builds on. This is a toy-regime result (Presburger arithmetic, 8
primitives, ~669K params); it makes no claim about the 1B, whose
generation gap is a separate problem with a separate binding constraint
(token scale + LR).

### Incidental fix: `canon` mod-precedence bug

`certificates.canon` rendered `mod(add(x0,3),7)` as `"(x0+3 mod 7)"`, but
the VRC parser binds `mod` tighter than `+` (term level), so that string
parses as `x0 + (3 mod 7)` — a different expression. ~20% of generated
specs round-tripped to a different target before the fix (8,137
roundtrip-mismatch skips in the first dataset run). Fixed by
parenthesizing compound mod arguments (`"((x0+3) mod 7)"`); regression
test `test_canon_parse_roundtrip` asserts `parse(canon(e)) == e` on 300
random exprs, 0 mismatches. All 4 Phase-1 suites (`test_vrc`,
`test_conditional`, `test_logic`, `test_noise`) still pass — `canon` is
display-only everywhere (certificate strings, verifier diagnostics).
